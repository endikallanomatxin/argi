# C interoperability

C interoperability uses typed declarations, explicit C-compatible representations,
and the target's C ABI. Ordinary Argi wrappers adapt foreign resources, buffers,
errors, and cleanup to the language's normal contracts.

## Functions and symbols

A `CFunction` declaration without a body imports an external symbol:

```rg
abs(.value: CInt) -> (.result: CInt) : CFunction

_abs(.value: CInt) -> (.result: CInt)
    : CFunction(.symbol = "abs")
```

The symbol defaults to the declaration's name. `.symbol` selects another linker
name without changing the Argi name or module visibility. Input names are local
binding information; C receives arguments in declaration order.

A declaration with a body implements a function with C ABI. Publication is
explicit and independent of the calling convention:

```rg
add(.left: CInt, .right: CInt) -> (.result: CInt)
    : CFunction(.export = true, .symbol = "argi_add") := {
    result = left + right
}
```

`.export = true` publishes the symbol; `.symbol` is optional here too. A body
without export uses internal linkage and can provide a C-compatible callback.
Export does not change
Argi's module visibility rules. Each published C symbol has one concrete
signature; Argi multiple dispatch does not overload a linker symbol.

A C signature has zero or one output. A returned struct is one typed output;
additional results use explicit pointer parameters. The compiler lowers
arguments and results according to the target ABI, including any required
register splitting or indirect return storage. The number of Argi output
fields does not select an ABI return convention.

## Foreign-call capability

Calling a foreign function requires access to a
`$&ForeignFunctionInterface` capability. The conventional dependency name is
`ffi`, supplied through the normal lexical `assume` and transitive `reach`
mechanisms:

```rg
main(.system: System) -> (.status_code: Int32 = 0) := {
    assume ffi ::= system.ffi
    value := abs(-42)
}
```

The capability is a checked Argi dependency, separate from the foreign
signature. It is not emitted as an extra C argument. Failure to supply it is a
compilation error. Wrappers may accept it as an ordinary Argi argument.
Imports reserve the logical argument name `ffi` for this dependency; C
parameters with that spelling must use another Argi name. Core resources that
call C, such as `Memory` and `File`, retain the capability supplied during
initialization so their operations can use it through the resource.

Authorization does not certify pointer bounds, resource effects, or the foreign
implementation's behavior.

Entering an exported function from C does not create a `System` or grant ambient
capabilities. An export that needs resources must obtain them through an explicit
context established by its host. A raw context address alone does not establish
validity or authorization. The same obligation applies to callbacks invoked by C.

## C-compatible types

Only types with a defined C representation may cross the ABI boundary by value.
Target-dependent scalar types such as `CInt` and `CLong` describe their C
counterparts; fixed-width integers and floating-point types can be used where
the external signature has matching representations.

C scalar names are aliases of the corresponding Argi builtin types, not a
separate arithmetic domain. Integer aliases include `CChar`, `CSignedChar`,
`CUnsignedChar`, `CShort`, `CUShort`, `CInt`, `CUInt`, `CLong`, `CULong`,
`CLongLong`, and `CULongLong`. `CSize` and `CPtrDiff` represent `size_t` and
`ptrdiff_t`; `CFloat`, `CDouble`, and `CBool` represent their C counterparts.
Plain `CChar` follows the target's default signedness. Compiler options that
change the C data model must match the bindings; non-default char signedness
is expressed with the explicit signed or unsigned alias.

C-compatible structs preserve the target's C field layout, padding, and
alignment:

```rg
Coordinates : CStruct = (
    .horizontal: Float64
    .vertical: Float64
)

Number : CUnion = (
    .integer: CInt
    .real: Float64
)

Status : CEnum = (
    ..ok = 0
    ..invalid = 3
)
```

`CUnion` fields share storage. Reading the appropriate field remains the
binding's responsibility; it does not have the discriminator of an Argi choice.
`CEnum` variants have no payloads and may declare explicit numeric values. Its
integer representation must match the external declaration.

Ordinary struct layout is not a C ABI guarantee. Arrays within records require
compatible element representations and C layout. `String`, `ArrayView`,
`Virtual`, and ordinary errable results require wrappers rather than being
passed as their Argi representations. Generic declarations must resolve to
concrete compatible signatures before crossing the boundary.

## Pointers and resources

`RawPointer#(.t: T)` represents a C pointer at the ABI boundary, not an Argi
record passed by value. It may contain a null address and does not establish
bounds, alignment, initializedness, or lifetime. An external pointer does not
become a safe `&T` or `$&T` merely because its declared pointee type is `T`.

Wrappers use `ArrayView` or `ArrayViewRO` for bounded buffers and lower them to
raw pointer/length parameters. C strings use explicit helpers from
`core/strings/c_strings.rg`. Foreign handles and their allocation/free pairing
remain explicit; cleanup can be provided by ordinary Argi `deinit` wrappers.
Reference construction must satisfy the [safety model](34_safety_model.md) and
[allocation contracts](35_allocation.md).

Headers do not reveal whether a call retains a pointer, frees storage, invalidates
views, or initializes a destination. The binding must establish these contracts;
the capability and C ABI compatibility checks do not infer them. Wrappers translate
C status codes into Argi errors, and exports translate Argi errors into explicit
C-compatible results instead of propagating them across the foreign boundary.

## Headers and linking

[Named header imports](02_modules.md#c-interoperability) produce the same typed
bindings as manual declarations. Include paths, defines, and target options
participate in translation and cache identity. Imported declarations do not
prove safety contracts or grant capabilities.

Library selection, search paths, and static/shared linking belong to build
configuration. Native CLI builds accept repeatable `--link-library <name>`,
`--link-static-library <name>`, `--link-shared-library <name>`,
`--library-path <path>`, and `--link-file <path>` options. Paths are relative to
the invoking working directory; inputs retain command-line order. Explicit
archive or shared-library files select that artifact, while names use the
platform linker's normal search policy.

Packages declare ordered native inputs in `argi.toml`:

```toml
[[native]]
search_path = "native/lib"

[[native]]
file = "native/lib/libexample.a"

[[native]]
library = "m"
```

Each entry has exactly one string field: `library`, `static_library`,
`shared_library`, `search_path`, or `file`.
These inputs apply to all package executables. Paths are relative to the package
root, including when its executable module is built directly; CLI inputs follow
manifest inputs and remain relative to the invoking directory. String values
are single-line quoted strings; use literal single quotes for paths containing
backslashes. Escapes in double-quoted native strings are not supported yet.
Builds and runs preserve entry order; no native dependency is downloaded or
compiled automatically. `library` uses the normal linker search policy;
`static_library` and `shared_library` require the requested artifact kind.
Explicit modes search the configured directories, then query the selected C
compiler for toolchain library paths. They select `.a` archives, Linux `.so`
libraries, or macOS `.dylib`/`.tbd` libraries without falling back to another
kind or changing the mode of subsequent inputs. Use `file` for versioned
libraries or artifacts outside those search paths. Shared libraries still
need to be available to the runtime loader; these options do not configure
installation or runtime search paths.

A symbol name identifies the declaration to resolve; a header
import does not implicitly download or select a library to link.

> [!IMPLEMENTATION]
> The compiler supports `CFunction` declarations, `.symbol`/`.export` options,
> and concrete scalar/pointer C-ABI bodies and exports. Foreign imports require
> a live `ffi` dependency without adding an argument to the C signature.
> Bundled `RawPointer<T>` values cross imports, bodies, and exports as C pointers;
> their ordinary Argi representation remains a record containing the address.
> `ExternFunction` remains a compatible spelling. C enums currently have ordinal `Int32` values; C-union
> storage is implemented.
>
> `CStruct` preserves native C field layout, including nested C records and
> fixed arrays with compatible elements. Empty records and fields without C
> representations are rejected. Generic C records retain their declared layout.
> Records can cross by pointer. Numeric C structs and unions cross by value on
> native Linux and macOS x86_64/ARM64, including integer and floating-point
> fields, nested records, fixed numeric arrays, and generic records. Signatures
> account for register exhaustion, by-value copies, indirect results, and ARM64
> homogeneous floating-point aggregates. Union alternatives share storage and
> are classified together; reading an appropriate member remains the binding
> contract. Struct fields may contain bundled `RawPointer<T>` values, including
> nested and generic structs. Foreign results retain raw-address provenance at
> those fields without creating validity roots or storage acquisition receipts.
> Safe-reference fields, raw-pointer arrays/unions, and over-aligned aggregates
> remain unsupported by value; header imports are not implemented. Scalar
> aliases currently select the native host target; selecting a cross-compilation target remains
> future work. `long double` has no supported alias. Existing
> low-level libc declarations still use references or native integers for several
> foreign pointer signatures. Aggregate call lowering is not a general C ABI
> implementation; unsupported by-value aggregate parameters/results and multiple
> outputs are diagnosed during checking. The symbol `main` remains reserved for
> the generated program entrypoint.
