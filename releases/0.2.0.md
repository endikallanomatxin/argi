# Argi 0.2.0

Argi 0.2.0 establishes a coherent safety and library foundation beyond 0.1.
The release combines temporal validity and ownership checking, checked bounded
storage, explicit allocator composition, virtual dispatch, and capability-based
error tracing. It also expands core collections and everyday text utilities.

Argi remains experimental. Language contracts, library APIs, and tooling may
change incompatibly between releases.

## Language and safety

### Temporal validity and ownership

The compiler tracks initializedness, moves, cleanup authority, storage roots,
and generations through calls and control-flow joins. Reinitializing storage
does not revive references from an earlier generation. Function summaries
carry these effects across ordinary, generic, recursive, and virtual calls.

Allocations own bytes and deallocation authority; initialized values and their
cleanup obligations are tracked separately. Opaque collection storage retains
its dependencies and ownership effects when values are moved or extracted.
Mutable references express write permission and remain aliasable.

### Checked bounded storage

Allocator receipts retain private physical bounds. Allocation-slot selection
checks containment and alignment, and arithmetic guards reject invalid sizes
and address-range wrap. Collection owners control occupancy independently of
raw slot handles. Array views cover initialized elements and retain their
backing lifetime; structural mutations invalidate dependent views and loans.

These guarantees cover the supported allocator/collection paths. Trusted
low-level operations retain caller proof obligations for physical validity;
arbitrary raw-pointer operations are not generally spatially safe. See
[the safety model](../description/34_safety_model.md) and
[allocation](../description/35_allocation.md).

### Explicit capabilities and virtual dispatch

`assume` enables named arguments lexically, with explicit arguments taking
precedence over assumptions and defaults. `reach` retains its separate role
of propagating dependencies through calls. The checked program entry owns its
resources and supplies `System` as a context of references.

`Virtual` uses a data pointer and a vtable pointer. Conversion can infer its
abstract from a contextual result type, and positional comptime type arguments
are supported. Method registries preserve receiver identity from the abstract
contract, including receivers that are not the first input. Conversion respects
concrete receiver permissions and validates erased method signatures.

### Errors and initialization

Error propagation uses an explicit virtual tracer capability. Errors retain
their original tracer reference, and safety rejects escapes beyond its storage
lifetime. Core supplies `NoopErrorTracer` and `FixedSizeErrorTracer`, with compact
source locations, bounded copied context, and fallible reporting. Fixed-size
tracers allocate during initialization; propagation does not allocate their
storage. `reset_context` clears diagnostic context while errors remain valid.
The fixed-size policy is a shared diagnostic log rather than an isolated frame
chain for each error.

Fallible initialization tracks success and failure separately before allowing
reads or cleanup of the destination. Anonymous aggregate and choice literals
receive contextual types. Incompatible typed numeric assignments are diagnosed
during semantizing, and rejected generic function bounds identify the required
abstract instead of reporting only a missing function.

## Core library

### Memory and allocator composition

`Memory`, `PageAllocator`, `GeneralPurposeAllocator`, and `ArenaAllocator`
compose through explicit backing capabilities. `System` exposes memory and page
allocator references without choosing application allocation policy. Allocating
functions take allocator inputs, and C allocation interoperation requires the
foreign-function capability.

### Collections

- `DynamicArray` and array views implement their applicable indexing, mutation,
  value-access, and resizing contracts.
- Generic equality search, reversal, binary search, and allocation-free heapsort
  operate through collection abstracts. Ordering uses explicit policies;
  binary search returns the first equivalent element in a sorted collection.
- `HashMap` and `HashSet` use explicit hash/equality policies with copyable keys
  and values. Integer and borrowed string-key policies are provided.
- `RingBuffer` provides a fixed-capacity owning FIFO, checked borrowed access,
  and cleanup of retained elements.

Indexed algorithms that copy values require `ImplicitlyCopyable`; owning-value
operations retain their separate transfer and cleanup contracts.

### Text and numbers

String views support byte-pattern search, prefix/suffix checks, ASCII trimming,
and allocation-free splitting. Join and replacement produce checked owning
strings with explicit allocators. String growth and allocation sizes are checked
before mutation. Fixed-width signed and unsigned integer parsing reports invalid
input and range failures without reinterpreting pointers as numeric conversions.

## Compiler and tooling

The compiler separates module-owned and linked whole-program graphs, using
stable identities and lookup indexes. Safety summaries use a dependency worklist
for fixed-point inference, and regression coverage compares summary effects with
concrete checking for representative ownership and initialization cases.

`argi check` validates every function body, including functions unreachable from
an executable entry. Normal builds retain reachability-based body validation.
`--release` selects optimized machine-code generation; build output controls can
emit LLVM IR, objects, or final executables, including across filesystem bounds.
Installed tools resolve bundled core from their installation prefix.

The supported local toolchain is Zig 0.16.x with LLVM 21. Native CI runs on Linux
and macOS. Validation evidence for the release candidate is tracked in
[the release plan](../plan/0.2.md).

## Migration

Choose an allocator explicitly when a function allocates. For example:

```rg
assume allocator ::= system.page_allocator
```

Construct general-purpose and arena allocators with their selected backing
allocator. Use `assume` for lexical omission of named inputs and `reach` when a
dependency must propagate through intermediate calls. Preserve the lifetime of
tracers and allocator backing storage while dependent errors or values remain
live. Follow the ownership and safety diagnostics when moving values or replacing
collection contents.

Further everyday language/library work is planned in [0.3](../plan/0.3.md), with
advanced runtime and domain work in [0.4](../plan/0.4.md).
