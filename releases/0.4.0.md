# Argi 0.4.0

Argi 0.4.0 introduces a checked bytecode engine for compile-time execution. The
same engine is also exposed through a persistent REPL and `argi run --vm`.
Also, it revises type and function definitions, simplifies error handling and
allocation, and adds CAD and HTTP libraries.

## Compile-time execution and VM

- Anonymous `#run` entries execute checked Argi code to produce scalar and
  aggregate constants. Computed `#if` conditions use the same execution engine
  to select code during compilation. Runtime references and resource owners
  cannot escape into compiler constants.
- The bytecode engine preserves integer widths, floating-point precision,
  reference lifetimes and selected cleanup. Native and VM execution share
  checked ownership and replacement rules. Host access and supported operations
  remain bounded; see the [execution scope](../docs/repl-acceptance.md).
- The same VM is exposed through `argi run --vm` and a persistent `argi repl`.
  The REPL retains values, definitions, imports and resource lifetimes across
  commands. Its prelude supplies output, allocation and tracing; terminal editing
  supports Unicode and multiline input.
- Rejected REPL submissions preserve accepted state; healthy reset and exit run
  cleanup. Traps and cancellation preserve completed effects and require reset.
  The REPL is stable within the documented scope, without full native backend
  parity or unrestricted FFI.

## Language and capabilities

- Types and functions are definition values. Struct and choice definitions have
  nominal identities; aliases preserve them. Compile-time parameters belong to
  the definition expression, using `Name := #(...) ...` for parameterized types
  and functions.
- Function inputs and outputs are ordinary record types, including named records.
  Calls and record construction share contextual typing and defaults. Contract
  implementations own their operation signatures; `Init#(Target, Args)` selects
  construction using nominal argument records and explicit or assumed inputs.
- Ordinary errors carry only their reason, so fallible library operations no
  longer require a tracer. `!` preserves existing errors and traces; `-> !!T` and
  `!! "context"` explicitly add diagnostic tracing through a caller-provided
  capability.
- `reach` is removed. Dependencies use ordinary inputs and lexical `assume`.
  Allocating APIs accept `Virtual#(Allocator)` by value, reducing allocator type
  parameters while retaining borrowed lifetimes and allocation cleanup evidence.

## Libraries

- An experimental [CAD kernel](../more/engineering/cad/README.md) provides
  sketches, polyhedral topology, profile extrusion, face editing and analytic
  surfaces, with runnable modeling examples. Boolean operations and arbitrary
  curved trimming remain unsupported.
- A new [HTTP/1 library](../more/network/http/http.md) provides bounded request
  parsing, streaming request bodies, fixed-length responses and stateful handlers
  with a blocking sequential server.
- `String` and `StringView` guarantee valid UTF-8; arbitrary bytes use byte
  collections/views and checked text conversion. Character literals represent
  `UnicodeScalar`, while C interoperability uses `CChar`.
- `HashMap`, `HashSet` and `PriorityQueue` each support copyable and movable
  elements through one type. Canonical borrowed queries and default hashing
  simplify map/set use; maps also support fallible explicit copying. Views,
  mutable access and moving iteration use consistent protocols and names.

## Compiler and editor

- Execution reuses checked code and reclaims unreachable VM temporaries while
  preserving live owners and published snapshots. Incremental compilation
  reduces repeated analysis and temporary memory retention.
- LSP syntax features respond ahead of background checking. Analysis reuses
  sibling buffers, cancels obsolete work and bounds retained memory. A full check
  that exceeds its budget can fall back to partial declaration navigation.

This release includes breaking changes to definition syntax, constructor
implementations, error/tracing signatures, dependency inputs, allocator handles,
and collection/view/text APIs.
