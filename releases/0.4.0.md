# Argi 0.4.0 — draft

Argi 0.4.0 brings nominal type values, persistent interactive execution and a
shared bytecode engine for compile-time evaluation. It also makes library APIs
and capability dependencies more consistent.

Release validation is still in progress. REPL stabilization is tracked in
[the acceptance notes](../docs/repl-acceptance.md).

## Types and functions

- Struct and choice definitions create nominal identities. Declarations bind
  values, aliases preserve identity, and generic specializations retain the
  identity of their definition and compile-time arguments.
- Compile-time parameters belong to definition values, using `#(...)` for both
  definitions and specialization. Generic definitions and named `once` function
  values preserve their identity through aliases and contract implementations.
- Function inputs and outputs use ordinary record types. Calls and record
  construction share contextual typing, field validation and defaults; named
  record types can be used directly as function signatures.
- Construction uses `Init#(Target, Args)` with nominal argument records and an
  associated result. Allocator types can be inferred from explicit or assumed
  inputs, without selecting constructors from their return types.

## Interactive and compile-time execution

- `argi repl` retains variables, owners, references, functions, types, contracts
  and imports across commands. Its visible prelude supplies output, allocation
  and tracing through ordinary lexical assumptions.
- The editor provides syntax colors, history, brace indentation, UTF-8 scalar
  editing and horizontal panning for long lines. Piped submissions use the same
  language semantics without terminal editing.
- `#run` declares an anonymous compile-time entry, with an optional host `System`
  input. It shares checked bytecode execution with computed `#if` conditions and
  the REPL; temporary resources and references cannot escape as constants.
- Rejected submissions preserve accepted state. Execution traps preserve effects
  already performed and require reset; healthy reset and exit run checked cleanup.
- The VM preserves integer widths and wrapping, IEEE floating-point precisions,
  references, partial initialization, selected cleanup and supported virtual
  dispatch. Native FFI and some memory operations remain restricted; see
  [the execution scope](../docs/usage.md#experimental-persistent-repl).

## Libraries and explicit dependencies

- `String` and `StringView` guarantee valid UTF-8. Arbitrary bytes use byte
  collections/views and checked text conversion. Character literals represent
  `UnicodeScalar`; C interoperability uses `CChar`.
- `HashMap`, `HashSet` and `PriorityQueue` each support copyable and movable
  elements through one type. Hash policies provide a canonical borrowed query;
  standard map/set construction supplies a default policy.
- Views share `Viewable`. Mutable access is named explicitly, including
  `MutableArrayView`, `get_mutable_reference` and `MutableReferenceIterable`;
  movement uses `MovingIterable`.
- Buffered readers and writers both borrow caller-provided buffers, including
  caller-scoped defaults. Text bounds checks and ASCII edits report errors.
  Stream and filesystem handling better preserves resources across partial I/O,
  POSIX interruptions and allocation failures.
- `reach` is removed. Dependencies belong in function inputs and can be supplied
  through `assume`. `error_tracer` has no automatic noop default; disabling traces
  requires explicitly supplying `NoopErrorTracer`.

## Compiler and tools

- Incremental sessions share a semantic graph with stable identities and
  transactional publication, reusing valid Safety proofs and bytecode bodies.
- Native and bytecode execution share checked replacement and cleanup plans.
  Disposable Safety tables are released independently of retained proof facts.
- Improved inference, missing-argument diagnostics and propagation of internal
  allocation failures, plus more consistent native path identity on Windows.

This release contains breaking language and library changes. Existing code must
migrate nominal record definitions, parameterized definition syntax, constructor
implementations, renamed collection/view APIs and explicit dependency inputs.
