# Argi 0.1.0

Argi `0.1.0` is an experimental release. The language, compiler API, standard
library layout and tooling behavior are not stable yet. Breaking changes are
expected.

## Goals

- Basic language features are well defined and implemented.
- Core library has basic utilities.
- Language tooling supports `build`, `test`, `lsp` and `init` commands.


## Language features

### Types

Argi `0.1.0` includes the initial type-system baseline:

- booleans;
- integers and floats;
- characters;
- aliases;
- explicit casts;
- basic type checks;
- pointers and references;
- read-only and read-write pointer modes;
- structs;
- public/private visibility boundaries;
- choices with payloads;
- optional/nullability flow;
- error unions;
- basic error propagation with `?`;
- `unwrap_or`, `unwrap_or_do` and `!`.

The release also includes the first coherent baseline for type identity,
refinement and dispatch rules across generics and abstracts.

### Bindings

The release supports:

- local bindings;
- mutable and immutable bindings;
- clear initialization rules;
- public and private module-level values;
- constant module-level initialization across files in the same folder module;
- diagnostics for reassignment, moved-from values and constant-initializer
  cycles.

### Functions

Function support includes:

- function declarations;
- named arguments;
- default arguments;
- positional and mixed call syntax;
- return values;
- implicit return with output defaults;
- compile-time parameters and generic functions;
- bounded type parameters;
- multiple dispatch;
- overload resolution across concrete, generic and abstract inputs;
- abstract contracts;
- `once` functions with single-consumption checking;
- a basic pipe operator.

### Modules

The module system supports:

- folder-based modules;
- named `#import(...)`;
- current, parent and project-root import resolution;
- bare imports through `more/`;
- module-qualified lookup;
- public/private visibility rules across imported modules;
- diagnostics for missing imports, import cycles and invalid cross-module
  access.

### Control flow

The release includes:

- `if` / `else`;
- `while`;
- `for` with iterators;
- `match`;
- `break`;
- `continue`.

### Memory management

Argi `0.1.0` includes the first ownership and memory-management baseline:

- ownership rules;
- copy and move rules;
- automatic `deinit`;
- structural auto-`deinit` for anonymous values;
- scope-based cleanup in loop bodies;
- value-position copyability checks;
- `copy()` / `deinit()` resolution baseline;
- `init(out: $&T, ...)` semantics;
- basic `$&` exclusivity in calls;
- non-owning copyability rules for views, pointers, slices and arrays;
- `keep`.

## Core library

### System

The initial `core` library includes a minimal `System` capability surface:

- argument count;
- argument access by index;
- borrowed `StringView` argument access;
- argument iteration;
- environment access;
- file-system open/read/write/append baseline;
- nominal error reasons through `Errable`;
- explicit capability handles;
- protection against implicit by-value copies of `System`.

### Strings

String support includes:

- owned `String`;
- borrowed `StringView`;
- string literals as read-only `StringView`;
- raw `&Char` C-string interop boundaries;
- conversion helpers at interop boundaries;
- string equality helpers and operator support;
- growable string push helpers with OOM reporting;
- formatting helpers based on `StringView`.

`String` remains the main growable text-buffer type in `core`.

### IO

IO support includes:

- `File`, `Reader` and `Writer`;
- `stdin`, `stdout` and `stderr`;
- byte IO;
- block IO over `ArrayView#(.t: UInt8)`;
- buffered wrappers;
- stream read/write/flush/close error reporting;
- EOF handling separated from stream failure reasons;
- text helpers such as `print`, `print_error`, `read_line()` and `read_file()`.

### Memory

Memory support includes:

- minimal allocator interface;
- fallible allocation helpers;
- arena/bump allocator;
- page allocator;
- allocator use across imported modules.

### Collections

Collection support includes:

- arrays;
- slices and views;
- range iteration;
- dynamic array baseline;
- dynamic array indexing and borrowed indexing;
- borrowed `for` iteration;
- hash map baseline;
- borrowed `StringHashMap#(.value: Type)` for compiler-style lookups.

Consuming/move-take collection iteration is deferred to a later release.

### Testing and diagnostics

The `core` library includes basic testing helpers:

- `core.testing.expect`;
- `core.testing.fail`;
- `core.testing.skip`;
- `core.testing.expect_equal`;
- `core.testing.expect_error`.

The compiler also includes regression coverage for diagnostics where wording
and behavior matter.

### C interop

C interop support includes:

- `CFunction`;
- raw `&Char` C-string boundaries;
- `ArrayView` adaptation at C interop boundaries;
- basic C enum interop;
- basic C union interop;
- calling-convention baseline.

## Tooling

Argi `0.1.0` includes the initial command-line tooling baseline:

- `argi build`;
- `argi run`;
- `argi test`;
- `argi lsp`;
- `argi init`.

### Build and run

The compiler can build and run folder-based projects using `argi.toml` package
metadata, configurable output paths and local `.argi-cache/` artifacts.

Compiler failures are reported as normal diagnostics without leaking internal
stack traces in regular CLI usage.

### Test runner

The native test runner supports:

- top-level Argi tests;
- generated test binaries under `.argi-cache/`;
- exclusion of tests from normal `argi build`;
- independent test roots for `once` analysis;
- `PASS`, `SKIP` and `FAIL` output;
- `--filter <name>`;
- visible compiler diagnostics when a test fails to compile.

### LSP

The LSP command includes an experimental language-server baseline:

- diagnostics;
- hover;
- inferred error reasons in hover;
- go to definition;
- references;
- rename;
- semantic tokens;
- module-aware definition support;
- incremental document lifecycle handling.

The LSP is not considered stable yet.

### Init

Project initialization supports project and module scaffolds.

Projects include a minimal application entrypoint. Modules create importable
folder modules without an executable entrypoint.

## Installation

Argi `0.1.0` installs the compiler and `core` together:

- `bin/argi`;
- `lib/argi/core`.

The compiler resolves `core` through a sysroot inferred from the executable path.
The sysroot can also be overridden with:

- `--sysroot <path>`;
- `ARGI_SYSROOT`.

`--sysroot` takes priority over `ARGI_SYSROOT`.

A development fallback to `./core` is kept for working inside the repository.
When `core` cannot be found, the compiler reports the searched paths and suggests
using `--sysroot` or `ARGI_SYSROOT`.

## Test coverage

This release includes regression and integration coverage for:

- language features;
- ownership and memory-management rules;
- module resolution and visibility;
- overload resolution;
- abstract contracts;
- choice and match typing;
- iterator behavior;
- C interop;
- core library behavior;
- CLI commands;
- LSP functionality;
- installed-toolchain smoke tests.

Selected diagnostics use exact stderr matching to protect user-facing compiler
output.

## Not included

Argi `0.1.0` does not include:

- stable language specification;
- stable compiler API;
- stable standard library;
- stable runtime model;
- formatter;
- package manager;
- stable LSP;
- `more` library;
- runtime model documentation;
- consuming/move-take collection iteration.
