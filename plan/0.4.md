# 0.4

## Release purpose

Introduce a shared execution model combining a bytecode VM and a JIT compiler.
Use it for a practical REPL and general compile-time execution, while preserving
Argi's capabilities, lifetime checking, error behavior, and deterministic cleanup.
This is the defining feature of the release after the broad foundations in
[0.3](../releases/0.3.0.md).

Bytecode execution provides immediate evaluation; JIT compilation provides native
execution for selected functions without requiring a separate language model.
Ahead-of-time LLVM builds remain supported. REPL and comptime use the same engine
with different session, capability, and persistence policies.

## Development order

1. Define executor contracts and the supported initial language subset. Settle
   host/target separation, runtime storage, capabilities, cleanup, and diagnostics
   before introducing bytecode instructions or native entrypoints.
2. Lower checked semantizing results into typed bytecode and implement the VM.
   Establish execution parity with existing ahead-of-time fixtures.
3. Add a persistent REPL with declarations, expressions, calls, error recovery,
   reset, and exit cleanup. Reuse modules and specializations across submissions.
4. Add a JIT tier with a shared call/storage contract, native-code lifetime
   tracking, VM/native transitions, and deterministic executor selection in tests.
5. Use the engine for explicit compile-time evaluation and compile-time
   conditions. Freeze supported results into compiler values and track inputs.
6. Validate end-to-end REPL, comptime, and mixed VM/JIT workloads, including
   resource cleanup, bounded memory, diagnostics, and measured latency.

Architectural dependencies and open decisions belong in
[the shared execution design](comptime_execution.md). Public comptime semantics
belong in [the language specification](../description/50_comptime.md).

## VM and JIT

- [ ] Define typed bytecode lowering, verification, value representations, call
  frames, branches, and source mappings from checked semantizing results.
- [ ] Execute scalars, aggregates, control flow, direct calls, specialized
  generics, Errable propagation, and ownership cleanup in the VM.
- [ ] Support explicit capabilities and validated storage/reference operations;
  reject unsupported operations with useful diagnostics.
- [ ] Compile selected functions through LLVM JIT, retaining source mappings and
  safe native-code ownership. Avoid a second implementation of language rules.
- [ ] Implement VM-to-JIT and JIT-to-VM calls with compatible values, frames,
  errors, cleanup, and output lifetime checks.
- [ ] Choose an initial tier policy from measurements; expose forced VM and JIT
  modes for validation. Automatic hot-code promotion can remain conservative.
- [ ] Define supported C/host-call bridges for runtime sessions and explicit
  comptime restrictions. Unsupported foreign signatures must fail predictably.

## REPL

- [ ] Add a CLI interactive session that accepts definitions and expressions,
  displays values and errors, and continues after a failed submission.
- [ ] Preserve definitions and module specializations across submissions with
  dependency-aware invalidation; do not repeat whole-program work unnecessarily.
- [ ] Define retained value roots, borrowing across submissions, and cleanup on
  reset/exit. Reject redefinition or unload that would invalidate live values.
- [ ] Keep failed submissions from committing partial definitions, while making
  already performed runtime effects explicit. Do not promise rollback of I/O.
- [ ] Exercise a practical session using collections and resource capabilities,
  with source-level traces and predictable lifetime diagnostics.

## Compile-time execution

- [ ] Implement explicit `#run` using the same VM/JIT engine, with ordinary
  checking and a defined compile-time capability/effect policy.
- [ ] Convert supported evaluation results into compiler constants, including
  owned aggregates; reject runtime handles and escaping evaluator references.
- [ ] Extend `#if` beyond target predicates using checked compile-time values,
  preserving discarded-branch import and diagnostic behavior.
- [ ] Track permitted external inputs in cache identity and reproducibility.
  Define recursion, instruction, memory, and wall-time limits where enforceable.
- [ ] Preserve compilation-target values and layouts during host execution;
  cross-target evaluation must not inherit host C aliases or pointer widths.
- [ ] Report errors with evaluation call traces and integrate failures with LSP
  diagnostics without allowing unbounded editor-time execution.

## Supporting compiler and tooling work

Fix compiler bugs that force library users to write more complicated code,
such as incompatible generic type spellings or incorrectly inferred errors.
Add a small regression test for each fix before building libraries on it.

- [ ] Fix contextual reason literals in inferred Errable outputs combining local
  errors with propagated imported errors.
- [ ] Normalize positional/named generic argument identities and carry contextual
  nominal types through aggregate assignments and generic error consumers.
- [ ] Improve failed-specialization diagnostics and audit transitive output
  dependencies where concrete executor or library consumers expose gaps.
- [ ] Schedule LSP diagnostics separately from interactive requests, coalesce
  edits, and discard stale results using dependency-aware invalidation.
- [ ] Add repeatable edit/evaluate benchmarks separating frontend, bytecode,
  native compilation, execution, and memory retention.

## Release acceptance

- [ ] A documented REPL usecase runs multiple submissions, preserves useful
  state, recovers after errors, and cleans resources on reset and exit.
- [ ] A mixed VM/JIT workload crosses both call boundaries and agrees with an
  ahead-of-time executable on values, errors, and observable cleanup.
- [ ] A comptime usecase computes an aggregate or specialization input with
  `#run` and exercises a computed `#if` condition, with dependency-aware reuse.
- [ ] Negative cases cover invalid cross-submission loans, stale code references,
  disallowed comptime effects, execution limits, and unsupported target behavior.
- [ ] Validate native execution on the supported platforms; explicitly document
  any supported-subset or platform limitations rather than silently falling back.

## Secondary work

HTTP/1, owning JSON consumers, streaming CSV, CLI subcommands, additional Python
packages, and BLAS are independent application candidates. They may demonstrate
the engine when useful, but they do not replace the REPL/comptime objective.
Generic C callbacks and bounded header imports follow concrete needs under
[C interoperability](c_interop.md). Native threads and synchronization remain in
[0.5](0.5.md); heavier execution and numerical domains remain in [0.6](0.6.md).
