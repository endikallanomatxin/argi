# 0.4

## Release purpose

Connect Argi to Python and support short interactive development cycles. Expand
practical application libraries with networking and a first numerical consumer,
building on the native/tooling foundations of [0.3](0.3.md).

## Development order

Follow **Python interoperability → interactive execution**, using C interop
and module reuse. Develop networking before HTTP, and a concrete matrix library
before BLAS integration. A VM/JIT is a candidate architecture, not a prerequisite
for the other work.

## Compiler, language, and tooling

- [ ] Enable Python to call native Argi libraries, following
  [Python interop](python_interop.md).
- [ ] Prototype persistent interactive execution and assess REPL/VM/JIT options,
  following [the execution direction](comptime_execution.md).
- [ ] Extend pipes to richer placeholders and qualified/generic calls after
  settling precedence and evaluation order.
- [ ] Evaluate local `Errable` handling sugar over ordinary reason matching.
- [ ] Extend virtual conversion to fully bound associated-parameter abstracts
  when required by a concrete consumer.

## Core library

- [ ] Add system entropy as a separate capability from deterministic PRNG state.
- [ ] Add address resolution and basic TCP/UDP with explicit socket lifetimes.
- [ ] Add a growable Deque when a queue consumer needs it.

## More library

- [ ] Add Python wrappers/examples over the native interoperability boundary.
- [ ] Add URI parsing/building and an HTTP/1 baseline after networking.
- [ ] Develop vectors/matrices with explicit storage and dimension contracts,
  including compile-time compatibility and dynamic-dimension checks.
- [ ] Add BLAS interop when a working linear-algebra consumer justifies it.

Concurrency and broader lifetime/storage extensions move to [0.5](0.5.md);
GPU and other heavier domains move to [0.6](0.6.md).
