# 0.4 — Shared execution

Goal: a shared bytecode VM/JIT for a REPL and compile-time evaluation.
Architecture: [comptime_execution.md](comptime_execution.md).

## Order

1. Define the initial subset, values/storage, calls, cleanup, and host/target boundary.
2. Extend replacement cleanup to runtime aliases and indexed storage, then extend partial initialization and error propagation.
3. Add persistent REPL sessions, failure recovery, reset, and exit cleanup.
4. Add LLVM JIT and checked calls in both directions between VM and native code.
5. Implement `#run`, computed `#if`, frozen results, and cache input tracking.
6. Validate against ahead-of-time execution on supported platforms.

## Supporting work

- Reproduce contextual Errable and generic type/aggregate issues before fixing them.
- Improve specialization diagnostics where executor consumers expose failures.
- Schedule LSP diagnostics separately; coalesce edits and discard stale results.
- Benchmark frontend, bytecode, JIT, execution, and retained memory separately.

## Acceptance

- REPL preserves state, recovers after errors, and cleans resources on reset/exit.
- VM/JIT calls agree with AOT on values, errors, and cleanup.
- A comptime example returns an aggregate and uses a computed condition.
- Negative tests cover stale loans/code, forbidden effects, execution limits,
  and unsupported target behavior.

Joint virtualization and broader symbolic constraints are deferred. Library
expansion and concurrency are independent of this release's execution goal.
