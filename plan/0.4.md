# 0.4

## Release purpose

Support short interactive development cycles and extend the optional Python
embedding introduced in [0.3](0.3.md). Expand
practical application libraries with HTTP and additional numerical consumers,
building on the native/tooling foundations of [0.3](0.3.md).

## Development order

Develop **interactive execution**, using C interop and module reuse. Build HTTP
on the existing networking library, and extend the existing dense linear-algebra
library with BLAS only for a concrete consumer. A VM/JIT is a candidate
architecture, not a prerequisite for the other work.

## Compiler, language, and tooling

- [ ] Extend C bindings with generic callbacks or bounded header imports only
  where a concrete consumer needs them, following [C interop](c_interop.md).
- [ ] Evaluate Python calling native Argi libraries when a concrete consumer
  requires it; keep it independent from embedding Python in Argi.
- [ ] Prototype persistent interactive execution and assess REPL/VM/JIT options,
  following [the execution direction](comptime_execution.md).
- [ ] Preserve contextual reason literals when inferred Errable outputs combine
  local errors and propagated errors from imported modules. Explicit reason
  sets currently provide a stable contract for typed package wrappers.

## More library

- [ ] Extend Python integration beyond the typed NumPy vector wrapper when
  concrete package consumers justify it; callbacks and shared buffers need
  explicit lifetimes.
- [ ] Add an HTTP/1 baseline using networking and URI components in `more`.
- [ ] Add BLAS interop when a working linear-algebra consumer justifies it.

Concurrency and broader lifetime/storage extensions move to [0.5](0.5.md);
GPU and other heavier domains move to [0.6](0.6.md).
