# 0.6

## Release purpose

Explore heavier numerical, GPU, protocol, and storage workloads on top of the
practical and concurrent foundations of [0.4](0.4.md) and [0.5](0.5.md).
Explore self-hosting as a real compiler workload for Argi. This is a direction
for later development, not a commitment to every candidate.

## Development order

Select a real workload before introducing specialized representations or public
APIs. Extend the shared VM/JIT execution model only where workloads justify
additional tiers or specialized lowering; concurrency remains independent.

## Compiler, language, and tooling

- [ ] Explore self-hosting by porting a compiler component to Argi, then assess
  gradual migration with a reproducible bootstrap from the Zig compiler. Use
  the experiment to identify language/library gaps; a full rewrite is not a
  prerequisite for closing the release.
- [ ] Explore GPU execution with explicit memory and platform boundaries.
- [ ] Extend the shared VM/JIT engine with additional optimization tiers or
  specialized execution when measured workloads justify the complexity.
- [ ] Evaluate a stable foreign virtual ABI for an actual integration need.
- [ ] Evaluate language controls for inlining/unrolling separately from safety.
- [ ] Evaluate an audit tool only for checks beyond compiler diagnostics.

## Core library

- [ ] Reassess compact/packed choice storage with a compiler/library workload.
- [ ] Reassess packed arrays, linked lists, ropes, SoA, and strided or
  multidimensional views with real consumers.

## More library

- [ ] Develop GPU utilities and heavier numerical/scientific libraries.
- [ ] Add HTTP/2 or other advanced protocols when application needs justify them.

## Beyond this horizon

Graphs, broad public platform APIs, advanced reflection, calendars/time zones,
debug binary formats, and a programmable build system remain unscheduled ideas
in `core/library_ideas.txt` and existing sketches.
