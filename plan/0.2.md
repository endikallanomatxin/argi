# 0.2

## Release purpose

Establish a coherent safety and library foundation beyond 0.1. This release
brings together temporal safety, checked bounded storage, explicit allocator
composition, virtual dispatch, and capability-based error tracing. Core gains
more useful collections and text operations, including generic hash maps/sets
and indexed collection algorithms.

Goals:

- Consolidate the implemented compiler and safety contracts.
- Publish the expanded core library with regression coverage.
- Close diagnostic gaps and validate the installed toolchain on Linux/macOS.

## Development order and scope

1. Resolve regressions in the supported compiler and library paths.
2. Validate the candidate, align help/documentation, and prepare release notes.
3. Publish through the repository release workflow when authorized.

The release is ready when those checks pass and preparation is complete.
Keep the implemented library scope; new language designs and system services
belong in [0.3](0.3.md), with advanced extensions in [0.4](0.4.md).

Language contracts live in `description/`; compiler architecture belongs near
its implementation. Remove completed tasks after validation.

## Compiler, language, and tooling

Remaining compiler work is limited to regressions found during release
validation; broader language and diagnostic designs are in [0.3](0.3.md).

## Core library

Keep the implemented library scope for this release and fix regressions found
in validation. Additional utilities and services are candidates in
[0.3](0.3.md#core-library).

## More library

Preserve existing modules and useful unfinished examples. Expansion into new
application domains belongs in [0.3](0.3.md#more-library) and
[0.4](0.4.md#more-library).

## Release preparation

Candidate `60670c05` passes the complete local suite: 1,163 tests (210 compiler
unit tests and 953 program tests). Both native jobs pass in
[CI run 36904011717](https://github.com/endikallanomatxin/argi/actions/runs/36904011717)
on Ubuntu 24.04 and macOS 15 with Zig 0.16.0 and LLVM 21.

An isolated installation outside the repository passes version/scaffolding,
build/run, optimized execution, and exhaustive checking. Representative
ownership, bounded-storage, virtual dispatch, error tracing, hash map, and
sorting programs pass execution and LLVM verification in development and
release modes. CLI help and safety documentation match the prepared scope.

Release notes and metadata are prepared in `releases/0.2.0.md`. Publication
uses the release workflow in `AGENTS.md` when explicitly requested. Development
work for this release is complete; new features follow the 0.3/0.4 roadmaps.
