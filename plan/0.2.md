## Prioritized compiler and safety follow-up

This checklist reassesses the static audit of `79a1e289` against `develop`
at `c64c91c4`. Priorities reflect correctness, language-contract clarity,
and implementation dependencies. Initial findings came from source inspection;
completed tasks are removed as validation and measurement refine this list.
Validation and measured comparisons are recorded in the relevant commits.
Pending investigation does not imply
a confirmed bug or a commitment to the proposed implementation.

### P1: Arithmetic and diagnostic gaps found during validation

- [ ] Define scalar grouping syntax without ambiguity with single-field
  values, and settle richer pipe/arithmetic precedence. Arithmetic now has
  conventional multiplicative/additive tiers with left associativity;
  parentheses still construct values. See `description/00_syntax_overview.md`.

### Completed spatial safety scope

The bounded library phase is complete for PageAllocator/Arena-backed
`DynamicArray`, initialized views, and checked allocation-slot selection.
Validation covers private acquisition receipts, move-only establishment,
range/alignment checks, arithmetic wrap, empty and nested subranges, owner
cleanup, backing reset, and forwarding summaries. The collection transition
audit covers owning-value replacement/extraction, initialized-prefix
relocation, repeated extraction, and growth/copy failure cleanup. Replacement
and structural mutations invalidate content loans, views, and iterators using
existing generations. Reference representation is unchanged.

This closes the supported bounded path for now. Allocators and low-level
`trusted_*` operations retain explicit proof obligations. The language contract
and owner-controlled occupancy rules are specified in
`description/34_safety_model.md` and `description/35_allocation.md`.

### Future spatial safety extensions

These are follow-up design candidates, not unfinished requirements of the
completed bounded-library phase. Reassess their release scope when a concrete
use case requires them.

- [ ] Design a general slot-owner API for ordinary initialization, borrowing,
  extraction, replacement, and cleanup. Repeated selection or copying of a
  `MaybeUninit<T>` handle does not establish exclusive authority. Validate
  owner-private occupancy, initialization failure, owning values, duplicate
  handles, and outstanding references before exposing reads. Prefer existing
  moves and generation invalidation over compiler tracking of arbitrary slot
  addresses.
- [ ] Evaluate certified bounded suballocation and external range import beyond
  the validated allocator/collection path. Specify which obligations are
  checked at runtime and which remain trusted. Ordinary `&T` certifies one
  object; adjacent selection must start from a bounded owner/region/view.
  Do not extend unbounded trusted offsets or reinterpretation with general
  pointer-arithmetic proofs.

### P2: Targeted performance work

- [ ] If repeated summary traversals remain significant, share traversal or
  invalidate dimensions selectively with explicit dependency tracking. Verify
  cross-dimension dependencies before skipping recomputation.

Profiling separates inference dimensions, state copying, virtual
merges/receiver lookup, summary allocation requests, and worklist capacity.
Initial focused measurements do not justify transactional rollback/COW;
keep clone/commit until a representative workload demonstrates a dominant
copying cost.
Merged virtual-summary work did not dominate the focused profiling corpus.
Defer cache epochs until larger workloads justify their complexity; cache
validity remains a correctness obligation whenever implementation summaries
change. Receiver positions now live in method registries: preserving the
abstract contract's receiver identity avoids guessing from concrete argument
types and also removes receiver scans during inference.

Capability-consumption review retains the existing known-alias domain:
move-only receipt establishment cannot revoke integer addresses inspected
before the move, including aliases forwarded through summaries. Regression
coverage verifies that these aliases observe consumption. Keep acquisition
authorization separate from Place moves and temporal roots; do not extend
this domain into general pointer-arithmetic proofs. Further simplification
needs an equivalent replacement for those guarantees and measured benefit.

### P3: Maintenance and platform confidence

- [ ] Consider separating global resolution/scheduling from diagnostic
  construction when changes expose a useful boundary. Large file size alone
  does not justify splitting `global/semantizer.zig` or `codegen.zig`.

Native CI validation is established on Ubuntu 24.04 and macOS 15 with Zig
0.16.0 and LLVM 21. Both complete-suite jobs passed for `652fc0fd` in
[run 36785579830](https://github.com/endikallanomatxin/argi/actions/runs/36785579830).
This closes the first-native-macOS-validation task; later compiler changes
still require their own CI results before claiming validation on both hosts.

## Language features

- ✅ Lexical `assume` arguments, with explicit > assumed > default precedence
- ✅ `reach` as a keyword, retaining transitive dependency propagation
- 📝 Fallible in-place `init`
  - ✅ Outcome-sensitive destination safety and `Errable<T, R>` constructor results
  - 💭 Track destination places reached through pointer parameters during
    direct calls to fallible initializers

- 📝 Advanced polymorphism
  - 📝 virtual types
    - [ ] Evaluate implementing virtual conversion for fully bound
      associated-parameter abstracts when a concrete use case requires it.
      Signature admissibility is specified in `description/134_virtual_types.md`;
      unsupported parameterized conversion now has a dedicated diagnostic.
    - [ ] Decide whether a stable foreign virtual ABI is needed; if so, specify
      slot ordering and external table construction independently of LLVM
      layout. The current two-pointer handle alone is not an ABI guarantee.

- 📝 Advanced functions
  - 📝 richer pipe operator with multiple placeholders
  - 📝 placeholders inside more complex expressions
  - 📝 builtins in richer pipe chains
  - 📝 qualified/generic pipe cases with settled precedence
  - 💭 closure model

- 📝 Module-level runtime initialization
  - 💭 non-constant top-level bindings
  - 💭 cross-file ordering semantics for folder modules
  - 💭 decide whether imported modules may run implicit runtime initialization
  - 💭 0.1 explicitly does not implement implicit init-on-import; keep current diagnostics until this is designed properly

- 📝 Error ergonomics
  - ✅ Implement tracer capabilities and original-tracer handles as specified
    in `description/59_errors.md`, including `NoopErrorTracer`, bounded
    storage, compact locations, and non-invalidating `reset_context`
  - 💭 `Errable`-specific `handle` sugar for consuming a local `Errable` into a final value
  - 💭 keep it as sugar over ordinary `match error.reason { ... }`
  - 💭 do not introduce value-returning blocks or new `return` semantics for this
  - 💭 require the shared result slot to be assigned on every handled error path
  - ✅ Preserve the original virtual tracer and reject errors escaping its
    storage lifetime; error payload cleanup does not own trace storage

- 💭 More advanced comptime. keep it minimal and only when it unlocks a
structural compiler/build-system need
  - ✅ Infer the abstract parameter of `to_virtual` from its contextual result
    type, including borrowed pipe results in typed `assume` declarations
  - ✅ Accept positional comptime type arguments in calls, including
    `to_virtual#(ErrorTracer)($&value)`
  - 💭 evaluate shared compile-time execution and interactive tooling in
    `plan/comptime_execution.md`

- 💭 Decide whether function inlining and loop unrolling need language-level
  controls. If in-place initialization later accepts uninitialized storage,
  define its safety rule explicitly rather than treating inlining as proof.

- 💭 Threading

- 💭 Runtime for async and concurrency copying zig's approach.
