## Prioritized compiler and safety follow-up

This checklist reassesses the static audit of `79a1e289` against `develop`
at `c64c91c4`. Priorities reflect correctness, language-contract clarity,
and implementation dependencies. Findings are from source inspection, not
suite results or measured performance. Pending investigation does not imply
a confirmed bug or a commitment to the proposed implementation.

### P1: Summary convergence and correctness

- [ ] Add systematic checker/summary parity cases: equivalent direct effects
  and effects through wrappers or summary application must preserve the same
  caller-visible state and rejection behavior. Cover move/deinit, aliases,
  opaque storage and generations, fallible initialization on both outcomes,
  recursion, and virtual dispatch. Existing wrapper regressions and summary
  unit tests are useful coverage, not an absence of tests; extend them with
  explicit paired cases rather than duplicating them indiscriminately.
- [ ] Extract shared transfer rules incrementally where parity work exposes
  duplicated semantics. Extend the primitive registry and shared state helpers
  where appropriate; keep symbolic composition and concrete validation
  distinct. Do not split `checker.zig`/`summary_infer.zig` by line count or
  attempt a single unified interpreter without evidence that it helps.

### P1: Spatial boundary and virtual language contract

- [ ] Complete the physical-range provenance work tracked under collections
  below. Specify who proves extent, alignment, initializedness, and physical
  origin for raw-pointer-to-reference conversion, allocation slots, reference
  offsets, and `ArrayView` construction. Include overflow-safe address/size
  arithmetic, subranges, and zero-length cases. Distinguish compiler proofs,
  runtime checks, and bundled trusted obligations; temporal roots and logical
  length checks do not prove these properties. Add positive/negative tests
  and useful diagnostics at each boundary. This is the next major safety
  feature, not a prerequisite for the small scheduler simplification.
- [ ] Reconcile `description/134_virtual_types.md` with the accepted virtual
  model: borrowed conversion, erased receiver and vtable, dispatch signatures,
  ownership/lifetimes, and safety merging. Codegen currently constructs two
  pointers, without the documented allocator/meta fields. Decide which layout
  and ABI guarantees belong to the language rather than freezing internal LLVM
  representation as a public ABI. Document accepted design normally, mark
  implementation gaps explicitly, and retain genuine open questions as such.

### P2: Error-tracer policy and targeted performance work

- [ ] Validate the shared-log `ErrorTracer` policy with multiple live errors,
  interleaved propagation, eviction, reset followed by reporting/propagation,
  and a different ambient tracer. Verify reporting failures use the noop
  tracer and that tracer lifetimes remain enforced. The tracer is already
  implemented; `description/59_errors.md` explicitly permits shared context
  and keeps errors valid across `reset_context`.
- [ ] Review whether per-error trace isolation is needed for diagnostic
  usability. If accepted, design trace identity and retention/reset semantics
  across the abstract API, creation, propagation, reporting, and storage before
  implementing them. `{generation, trace_id}` is a candidate, not an accepted
  requirement; invalidating error handles on reset would conflict with the
  current contract. Do not reclassify intentional shared logging as a proven
  memory-safety defect.
- [ ] Profile remaining safety costs after scheduler simplification, using
  existing `state_clones`/`state_elements_copied` counters and new inference
  counters as needed. Include calls, branches, loops, and allocator composition.
  Account for retained summary allocations and worklist growth as well as
  state copying; fewer evaluations may reduce both time and memory.
- [ ] If measurements justify it, reduce transactional state copying with
  checkpoints/deltas or partial copy-on-write. Preserve rollback, branch joins,
  loop convergence, and failure-path isolation; choose the mechanism after
  profiling rather than committing to a rewrite now.
- [ ] If repeated summary traversals remain significant, share traversal or
  invalidate dimensions selectively with explicit dependency tracking. Verify
  cross-dimension dependencies before skipping recomputation.
- [ ] If virtual inference remains significant, index the receiver position
  instead of scanning `virtual_calls`, and replace repeated cache clearing
  with dependency-aware versioning. Cached merges, including invalid results,
  must observe implementation summary changes; preserve the final cache reset
  needed before concrete checking until an equivalent mechanism exists.

### P3: Maintenance and platform confidence

- [ ] Clean `description/133_abstract_types.md` and `core/core.md`: separate
  accepted design from questions/ideas, remove stale inventory and generated
  brainstorming labels, fix English/typos, and move actual scheduling to plans.
- [ ] Correct `AGENTS.md` test paths and commands to use the current
  `tests/feature_tests/<category>/<case>/main.rg` organization, while retaining
  the folder-module rule and documenting any other test groups as appropriate.
- [ ] Consider separating global resolution/scheduling from diagnostic
  construction when changes expose a useful boundary. Large file size alone
  does not justify splitting `global/semantizer.zig` or `codegen.zig`.
- [ ] Isolate platform-specific page-allocation constants/calls and replace
  the build's external `rm` dependency with a suitable build-system operation.
- [ ] Add macOS validation with compatible Zig/LLVM and core runtime tests
  before treating Linux/macOS support as equally verified. Current CI only
  runs Linux; platform flag values alone do not establish a portability bug.

## Language features

- ✅ Lexical `assume` arguments, with explicit > assumed > default precedence
- ✅ `reach` as a keyword, retaining transitive dependency propagation
- 📝 Fallible in-place `init`
  - ✅ Outcome-sensitive destination safety and `Errable<T, R>` constructor results
  - 💭 Track destination places reached through pointer parameters during
    direct calls to fallible initializers

- 📝 Advanced polymorphism
  - 📝 virtual types

- 📝 Advanced functions
  - 📝 richer pipe operator with multiple placeholders
  - 📝 placeholders inside more complex expressions
  - 📝 builtins in richer pipe chains
  - 📝 qualified/generic pipe cases with settled precedence
  - 💭 closure model

- 📝 Module-level runtime initialization
  - 💭 non-constant top-level bindings
  - 💭 cross-file ordering semantics for folder modules
  - 💭 decide whether imported modules may run implicit runtime initialization
  - 💭 0.1 explicitly does not implement implicit init-on-import; keep current diagnostics until this is designed properly

- 📝 Error ergonomics
  - ✅ Implement tracer capabilities and original-tracer handles as specified
    in `description/59_errors.md`, including `NoopErrorTracer`, bounded
    storage, compact locations, and non-invalidating `reset_context`
  - 💭 `Errable`-specific `handle` sugar for consuming a local `Errable` into a final value
  - 💭 keep it as sugar over ordinary `match error.reason { ... }`
  - 💭 do not introduce value-returning blocks or new `return` semantics for this
  - 💭 require the shared result slot to be assigned on every handled error path
  - ✅ Preserve the original virtual tracer and reject errors escaping its
    storage lifetime; error payload cleanup does not own trace storage

- 💭 More advanced comptime. keep it minimal and only when it unlocks a
structural compiler/build-system need
  - ✅ Infer the abstract parameter of `to_virtual` from its contextual result
    type, including borrowed pipe results in typed `assume` declarations
  - ✅ Accept positional comptime type arguments in calls, including
    `to_virtual#(ErrorTracer)($&value)`
  - 💭 evaluate shared compile-time execution and interactive tooling in
    `plan/comptime_execution.md`

- 💭 Decide whether function inlining and loop unrolling need language-level
  controls. If in-place initialization later accepts uninitialized storage,
  define its safety rule explicitly rather than treating inlining as proof.

- 💭 Threading

- 💭 Runtime for async and concurrency copying zig's approach.
