# 0.2

Goals:
- More advanced language features are well defined and implemented.
- Core library grows beyond basics.
- `more/` has a few key modules for real programs.
- Language tooling includes `audit` and `format` commands and improves in
reliability and ergonomics.

with tests covering the implemented features and protecting against
regressions.

## Language features

- ✅ Lexical `assume` arguments, with explicit > assumed > default precedence
- ✅ `reach` as a keyword, retaining transitive dependency propagation
- 📝 Fallible in-place `init`
  - ✅ Outcome-sensitive destination safety and `Errable<T, R>` constructor results
  - 💭 Track destination places reached through pointer parameters during
    direct calls to fallible initializers

- 📝 Advanced polymorphism
  - 📝 virtual types

- 📝 Advanced functions
  - 📝 richer pipe operator with multiple placeholders
  - 📝 placeholders inside more complex expressions
  - 📝 builtins in richer pipe chains
  - 📝 qualified/generic pipe cases with settled precedence
  - 💭 closure model

- 📝 Module-level runtime initialization
  - 💭 non-constant top-level bindings
  - 💭 cross-file ordering semantics for folder modules
  - 💭 decide whether imported modules may run implicit runtime initialization
  - 💭 0.1 explicitly does not implement implicit init-on-import; keep current diagnostics until this is designed properly

- 📝 Error ergonomics
  - 💭 `Errable`-specific `handle` sugar for consuming a local `Errable` into a final value
  - 💭 keep it as sugar over ordinary `match error.reason { ... }`
  - 💭 do not introduce value-returning blocks or new `return` semantics for this
  - 💭 require the shared result slot to be assigned on every handled error path
  - ✅ Release compiler-allocated error trace entries through runtime `free`
    when an error payload is cleaned up

- 💭 More advanced comptime. keep it minimal and only when it unlocks a
structural compiler/build-system need
  - 💭 evaluate shared compile-time execution and interactive tooling in
    `plan/comptime_execution.md`

- 💭 Decide whether function inlining and loop unrolling need language-level
  controls. If in-place initialization later accepts uninitialized storage,
  define its safety rule explicitly rather than treating inlining as proof.

- 💭 Threading

- 💭 Runtime for async and concurrency copying zig's approach.


## Core library

- Strings
  - 💭 better formatting and text helpers

- 📝 More collections
  - ✅ `MaybeUninit<T>` slot handles for `DynamicArray`
  - 💭 define a language-level runtime safety failure diagnostic
  - ✅ `abort` is a diverging statement recognized by semantizing and lowered to a runtime trap
  - 💭 enforce physical range provenance when constructing array views from
    low-level pointers, in addition to their runtime logical-length checks
  - 💭 sets
  - 💭 queues / deque
  - 💭 consuming iteration
    - 💭 `for ~ item` / consuming iteration
    - 💭 `TransferIterable` and collection-consuming iterators
    - 💭 `~arr[i]` / move-take from collections if that needs separate place semantics
    - 💭 `DynamicArray#(.t: String)` plain value access with allocator-aware copies

- 📝 System
  - ✅ reference-only System with resource ownership in a safety-checked entry wrapper
  - ✅ explicit `Memory` and `PageAllocator` capabilities, with allocator
    backing chains chosen by programs
  - ✅ unbuffered terminal streams and explicitly allocated stateful wrappers
  - ✅ reuse freed general-purpose allocator slots through their bitmap
  - 💭 establish allocator metadata in-place before publishing references to
    initialized metadata; current initialization uses private trusted helpers
  - 💭 resolve allocator-summary incompatibility when a `GeneralPurposeAllocator`
    uses an `ArenaAllocator` as backing storage; summary fresh-root effects
    currently conflict with the arena's regional lifetime model. The canonical
    `PageAllocator` → `GeneralPurposeAllocator` → `ArenaAllocator` chain works.
  - 💭 networking basics
  - 💭 interacting with ports
  - 💭 TCP / UDP socket baseline
