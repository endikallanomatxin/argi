# 0.3

## Release purpose

Make Argi easier to develop with and useful for native tools and libraries:
faster rebuilds, practical C interoperability, cross-compilation, and native
Windows support. Add small everyday utilities without coupling the release to
networking, concurrency, or a new execution engine.

## Development order

Fix correctness gaps first, then source formatting. Library work starts with
small utilities, then time and processes. Move unfinished independent work forward rather than
expanding the release indefinitely.

## Compiler, language, and tooling

- [ ] Improve runtime safety diagnostics beyond bare traps.
- [ ] Improve diagnostics for unresolved imported types and incompatible
  assignments that currently reach internal errors or codegen.
- [ ] Support array element reads from temporary record results.
- [ ] Fix empty numeric constructors inside generic bodies; they currently
  produce aggregate values that cannot be lowered as scalars.
- [ ] Fix large aggregate returns through caller-owned return storage; the
  current ABI exposes an LLVM crash with `zeroed#(.t: [65536]UInt8)()`.
- [ ] Track fallible initialization destinations reached through pointer inputs.
- [ ] Settle scalar grouping/arithmetic precedence and ordinary integer
  widening/explicit conversions.
- [ ] Implement basic source formatting.
- [ ] Revisit summary traversal, state copying, virtual-summary caching, and
  proven alignment checks only where profiling identifies meaningful costs.
  Split global resolution/diagnostics only when a useful boundary emerges.

## Core library

- [ ] Add float parsing and address concrete numeric formatting gaps.
- [ ] Share formatting between strings and writer sinks, allowing text and
  numbers to be printed without intermediate owning strings.
- [ ] Add a deterministic seedable PRNG; keep system entropy separate.
- [ ] Add duration, monotonic/wall-clock time, and sleep through capabilities.
- [ ] Add process spawn/wait, exit status, streams, and termination.

## More library

- [ ] Add semantic-version parsing, comparison, and formatting for tooling;
  reassess placement if a core consumer needs it.

The next release, [0.4](0.4.md), builds application libraries and interactive
workflows on these foundations. Keep language contracts in `description/` and
remove completed planning items after validation.
