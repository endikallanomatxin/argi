# 0.5 — Capability views and concurrent safety

Argi permits mutable aliasing within an execution. The checker preserves
temporal validity, storage generations and cleanup obligations. Concurrent
sharing and ownership transfer add distinct requirements to those existing
checks. Use explicit trust at the type owner's boundary to certify concurrent
operations.

## Implementation order

1. **Compose single-capture capabilities.** Erase the entire reference type.
   Verify each implementation against the public operation guarantees.
   Preserve the captured authority and temporal dependencies independently.
   A dynamic call uses the verified interface and the retained capabilities
   even when its concrete method is unknown.
2. **Complete owning transfer in both directions.** Prove use and cleanup of
   Allocation and String from their retained capabilities. Separate that
   proof from liveness, overlap and ownership. Exercise one nominal type
   with local and concurrent deallocation, forwarding, alias replacement,
   mixed joins, successful return, and failed submission or result discard.
   Keep exclusive loans available for sequential use across executions.
3. **Simplify and measure.** Remove checker rules that duplicate the
   interfaces, capability evidence or the execution handoff. Test separately
   compiled or opaque wrappers and seek cases with unknown targets or
   incompatible alternatives. Compare compile time, peak memory, generated
   code size and specialization counts under the same workload.
4. **Bind multiple participants.** Resume joint capture once the single
   reference model works through ordinary calls, virtual dispatch and
   execution boundaries. Use one borrowed context and preserve each
   capture's lifetime, access authority and overlap obligations.

[Virtual capability binding](virtual_capabilities.md) and
[static transfer evidence](transferability.md) specify the integration cases.
The [resource authority research](resource_authority.md) records prior
experiments. General protocol inference and ordered resource transformers are
outside the implementation gates above. Pending sequential safety
counterexamples remain independent requirements.
