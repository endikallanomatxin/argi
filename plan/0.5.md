# 0.5

## Release purpose

Support concurrent programs and reusable execution services. Extend lifetime
and storage mechanisms where real consumers need them, keeping the language's
explicit capabilities and deterministic cleanup.

## Development order

Develop **atomics → OS threads → synchronization → tasks/runtime**. Settle
cross-thread lifetimes, cancellation, and cleanup before exposing async APIs.
Language/storage extensions are independent candidates, not requirements for
all concurrency work. This horizon follows [0.4](0.4.md) and remains adjustable.

## Compiler, language, and tooling

- [ ] Define retained foreign callback/context lifetimes and cleanup when a
  consumer needs registration, following [C interop](c_interop.md).
- [ ] Define cross-thread value/reference rules and concurrency safety boundaries.
- [ ] Develop a task/runtime model over validated native thread primitives.
- [ ] Define closures with explicit capture and lifetime rules.
- [ ] Settle module-level runtime initialization and cross-file ordering.
- [ ] Evaluate general slot-owner APIs and certified bounded suballocation or
  external ranges for concrete consumers, preserving existing safety contracts.
- [ ] Evaluate consuming iteration without assuming proposed syntax is accepted.
- [ ] Evaluate package management after package identity, versions, dependency
  resolution, and build inputs are settled.
- [ ] Extend platform/target coverage when actual consumers need it.

## Core library

- [ ] Add atomics, thread handles, and synchronization alongside compiler rules.
- [ ] Add cancellation and cleanup support for tasks/runtime.
- [ ] Evaluate in-place allocator metadata initialization when useful.

## More library

- [ ] Exercise concurrency with a concrete worker or server application.
- [ ] Extend networking/HTTP with WebSockets or RPC when that consumer needs it.

Specialized execution and storage remain in [0.6](0.6.md), rather than becoming
prerequisites for the first concurrent programs.
