# 0.5 — Resource authority foundations

The immediate priority is a small, compositional safety model, not broader
scheduling support. The proposed rules and implementation gate are in
[the resource authority core](resource_authority.md). The
[concurrency research](concurrency.md) and
[virtual execution investigation](virtual_execution_safety.md) retain the design
history and concrete compiler gaps.

The current native backend supports plain results and checked nonowning loans.
It does not yet transfer general owners or guarantee ordinary-memory race freedom.
Keep sequential mutable aliasing and two-pointer Virtual handles by default.
Conservative call-entry authorization remains the baseline until bounded resource
transformers justify more precise authority transitions. Ownership, access
authority and operation execution requirements are distinct; access footprints
do not certify synchronization.

The native join/entry increment and independent inline execution landed in
fd36db6e6; the authorization/composition gate remains open. The next checkpoint
is [safety across abstraction boundaries](resource_abstraction.md): specify
invariants, sound forgetting, interface guarantees and transitions; challenge
them with counterexamples; then map them to existing checker facts. Do not start
by extending routes, permissions or synchronization implementations. Precise
erased element histories and general resource transformers remain optional
precision work, not prerequisites for every safe concurrency abstraction.
Formalize [internally acquired authority](resource_abstraction.md#authority-obtained-inside-an-operation)
as the next contrast: protected ownership, a guard, and a balanced update helper.
An effect bound must remain visible even when a verified protocol supplies the
authority; a protected access must not conceal an unprotected one to the same region.
The executable model now composes acquisition-derived grants with the existing
loan ledger, including nested loans that prevent release. Compiler witness
fixtures check reuse of retained validity dependencies without new primitives.
These checks support conservation; they do not implement protected sharing or
close the physical/opaque authorization gate.
Separating captured-observation validity from concurrent authorization now lets
the after-completion collection case use its interface without exact target
recovery. Changed captures still reject, including nested delegation. The bounded
active-loan common-contract case now passes using authenticated backing
observations; general abstract physical extent publication remains open.
The next reduced implementation gate is [reference observations through checked
views](reference_observations.md). It separates exact identity from backing
derivation and requires must-guarantee joins before propagating earlier observations.
Protocol identity is now explicit in the bounded experiment: a subview cannot
split one mutex's custody into independently acquirable locks. Keep that relation
separate from physical view identity when designing public protocol guarantees.

## Development gates

1. **Specify and challenge the Resource Machine.** Use
   [resource_authority.md](resource_authority.md) as the semantic reference.
   First close the bounded [abstraction checkpoint](resource_abstraction.md).
   Treat modular usability as an acceptance criterion alongside soundness:
   public guarantees must suffice without inspecting hidden implementations.
   Define storage/observation identity, overlap, grants, responsibility and exact
   protocol obligations; give operational rules independent of library names.
   First specify lending, certified reclaim, accepted handoff and prepared
   cancellation against the current native adapter. Separate logical discharge
   from authentic quiescence and publication. Challenge wrong-instance and
   fabricated certificates, partial start failures and worker-entry storage.
   Specify the abstraction from compiler
   facts to machine states and convergence of its summary domains. Keep explicit
   limits on inference and reusable interface guarantees. A mechanized proof can
   follow stable rules; the finite experiments are not that proof.
2. **Close authorization and native-evidence gaps together.** Route direct,
   ordinary, virtual, callback, native and cleanup accesses through the same rule.
   Unknown effects require confinement evidence or conservative rejection.
   Acquisition presence is now checked separately from consumption and origin
   metadata. This is not the final abstraction story: a verified abstract factory
   must be able to publish usable physical-storage evidence without exposing its
   provider. Define and validate that common guarantee for both fresh backing
   and checked subranges; do not make permanent rejection of ownership-only
   factory results a substitute for completing the interface.
   Specify authenticated extent, initialization, publication and reclamation for
   native buffers; compare existing acquisition protocols before adding evidence.
   Preserve valid borrowed await and forwarding executors. Establish an end-to-end
   gate: plain borrowed task input, authenticated result access, matching completion,
   valid cleanup, and rejection of conflicting unknown calls. Cover copied handles,
   wrappers, indirect/native calls, failure and unrelated pending tasks. Do not
   merge a gate that merely changes the positive tests to expect rejection.
   Validate an independent inline executor using the same once-only handoff
   guarantees as the threaded backend. Keep entry-authority fallback and existing
   conservative completion-before-access rejections. A bounded compositional
   transformer is optional later precision work, with reversed-order, wrong-receipt,
   failed-completion and branch/loop negatives; no library-name exemption or
   general ordered-effect graph.

   Implemented milestone: [uniform unknown-call authorization](unknown_call_authorization.md)
   preserves 121/177, borrowed await and the executor cases. General physical
   extent publication and the rest of this stage remain separate obligations.
   [Mutation alternatives](conditional_reference_mutation.md) must also survive
   before a loan starts: a correct call gate cannot repair stale returned facts.
   Reference-leaf snapshots cover the documented local record replacements;
   partial may-target lists still do not establish complete alias information.
   [Body reference witnesses](body_reference_summaries.md) now widen bounded
   plain-reference result summaries from entry-relative origins observed by the
   temporal visitor. This avoids another array-specific alias recognizer;
   unknown origins, aggregate results and resource-bearing outputs remain open.
   [Reference target coverage](reference_target_coverage.md) distinguishes known
   candidates from uncovered alternatives and prevents unjustified definite
   updates and loans. Residual writes to unrepresented destinations remain an
   open soundness obligation, with a compile-only counterexample.
3. **Demonstrate complete owner transfer.** Start with a known destructor without
   external resources, then retain a borrowed dependency, then a virtual
   deallocator. Preserve responsibility, authority and cleanup through success,
   failure, discard and opaque storage, using the existing executor.
4. **Demonstrate verified sharing.** A mutex owns protected storage and grants
   scoped authority through a guard. Earlier outside aliases cannot bypass it;
   guard-derived references become unusable before release. Exclusion and memory
   publication must have certified runtime implementations.
5. **Validate composition and ergonomics.** Repeat those cases through generic
   calls, contracts, Virtual and collections. Measure compilation costs and check
   that ordinary callers do not need to manage region annotations. Prefer common
   certified contracts or rejection when heterogeneous extraction loses evidence.

Advance beyond these gates only if shared references, owner transfer with external
cleanup, and a mutex can be explained by the same rules. Dynamic conformances
remain a later option, not the basis of the model.

## Later work

Certified partitioning, channels, task groups, backend-independent waiting,
cancellation, worker pools, serialized/local executors and green threads remain
valuable directions. They are not simultaneous requirements for 0.5. Keep their
protocols compatible with the core without implementing them all now.

System.executor integration still requires native-only virtual methods to coexist
with System-based VM and compile-time execution. Resolve that implementation
constraint without bypassing safety.

Unscheduled: explicit closure captures, module runtime initialization,
slot-owner/suballocation APIs and additional platforms. Other topics have their
own notes in this directory.
